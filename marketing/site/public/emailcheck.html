03 - WHY

Built for the boring part

Reasons, not just a boolean

Every verdict ships with the signals behind it: which MX hosts answered, which flag fired, what the score costs. No black box you have to reverse engineer.

Edge cached DNS

MX and TXT lookups are cached per data centre for 10 minutes, so a warm call costs ~10ms instead of 300ms. Bulk cleaning stays cheap.

Honest about the limit

No SMTP handshake happens at the edge, so we never claim to prove a mailbox exists. We tell you whether the domain accepts mail and how risky the address looks.

06 - FAQ

Questions we get asked

Does it tell me if a specific inbox exists?

No, and neither can any API that runs at the edge. We verify the domain accepts mail (MX + fallback A records), classify the address (disposable, role, free, typo) and score it. Be suspicious of any cheap API that claims otherwise.

How many addresses can I send per call?

100 on /v1/bulk. Send parallel requests for larger lists; bulk requests are de-duplicated and DNS is cached so throughput scales with concurrency, not with the list size.

What is the canonical form for?

De-duplication. Gmail ignores dots and anything after a plus sign, so jane.doe+news@gmail.com canonicalises to janedoe@gmail.com. Use it as a unique key and you stop paying for the same lead twice.

Is the disposable list maintained?

It is generated from the public disposable-email-domains blocklist (10,400 domains at build time) and ships inside the Worker, so lookups are a set membership test with no network round trip.
