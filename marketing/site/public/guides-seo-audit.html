The on-page audit you can run in one request

Titles, headings, canonical, structured data, alt coverage and weight. All of it is in the HTML you already have. A crawler is optional.

What actually moves on-page

Backlinks and authority are not on the page. Everything else is: title length, meta description, one H1, heading order, canonical, robots directives, structured data, image alt text, internal link count, page weight and response time. Those are the things a template regression breaks first.

The request

curl -s 'https://seo-audit.p.rapidapi.com/v1/audit?url=https://example.com' \
  -H 'X-RapidAPI-Key: YOUR_KEY' \
  -H 'X-RapidAPI-Host: seo-audit.p.rapidapi.com'
const res = await fetch('https://seo-audit.p.rapidapi.com/v1/audit?url=' + encodeURIComponent(pageUrl), {
  headers: { 'X-RapidAPI-Key': process.env.RAPIDAPI_KEY, 'X-RapidAPI-Host': 'seo-audit.p.rapidapi.com' }
});
const audit = await res.json();
console.log(audit.score, audit.findings.map(f => f.id));

Other endpoints on the same API

  • GET /v1/meta: head tags only, the fast path when you do not need the body.
  • GET /v1/links: internal and external links with anchors and rel attributes.
  • GET /v1/keywords: term frequency and TF-IDF for a page or raw text.
  • GET /v1/readability: Flesch, Flesch-Kincaid and Gunning fog.
  • GET /v1/robots and GET /v1/sitemap: parse both files without another dependency.
  • POST /v1/text: readability plus keywords on text you already have.

What the audit cannot do

  • It does not measure backlinks, domain authority or rankings.
  • It does not read Search Console. Clicks and impressions are yours, not ours.
  • If the site blocks bots, the response says so. It will not invent a score.
