02 - WHY THESE

Narrow scope, verifiable behaviour

One Worker per product

No shared mega-service. A bug in the document parser cannot take down email verification, and each API has its own limits, quotas and release cadence.

Deterministic first

Where a rule beats a model, we use the rule. Keywords, entities, PII, DNS and scoring are code, which means identical input gives identical output and your tests stay meaningful.

Failure is documented

Every endpoint lists its error codes, size caps and timeouts in the OpenAPI document. When something is not supported we say so instead of returning a plausible looking empty response.

The code is public: github.com/ayam04/ayam-labs-apis. Read the guard, the SSRF checks and the tests before you pay for anything.

04 - PRINCIPLES

What we will not do

No resale of other people's data

Every API here computes something from input you send, or fetches a page you asked about. None of them resell scraped social profiles, private datasets or someone else's licensed feed.

No stored payloads

Documents, emails, page bodies and text are processed in memory inside the request and discarded. What gets logged is the route, status, duration and a request id.

No mystery boxes

If a verdict is a heuristic, the response says so and lists the signals behind it. When we cannot verify something, we return unknown rather than guessing for a nicer looking number.

No dark limits

Size caps, page limits, truncation flags and rate limits are in the spec and in the response. You should never discover a limit in production.

Start with pay as you go

$0.05 a call, no monthly minimum. Wire up the integration, see exactly what it costs, then move to a monthly plan when the volume makes it cheaper. Both happen on the same listing in one click.
